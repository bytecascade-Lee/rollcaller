# CHANGELOG.md 书写规范

> 本文档定义了 `CHANGELOG.md` 的书写规范，适用于项目所有贡献者。

---

## 一、定位

**CHANGELOG 面向开发者**，回答的问题是： **“代码层面发生了什么变化？”**

- 记录代码/架构层面的变动
- 帮助排查 Bug、追溯历史、评估升级风险
- 不面向最终用户，不写产品描述

---

## 二、版本号规则

### 版本格式

```
## [版本号]
```

- 版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)：`主版本号.次版本号.修订号`
- 预发布版本附加 `-alpha.x` / `-beta.x` / `-rc.x` 后缀

### 版本排序

**按时间倒序排列**，最新版本在最上方。补丁版本单独成章，与其他版本一同维护。

### 补丁版本处理

补丁版本（修订号递增，如 1.0.0 → 1.0.1）是正式的发行版本：

- 每个补丁版本**单独成章**，不被合并或汇总到任何其他版本中
- 补丁版本按时间倒序排列，与其他版本一同维护
- 下一个次版本号或主版本号发布时，补丁版本的历史记录**保留不变**
- 章节结构可酌情精简（省略 Added、Removed 等章节），但 **Fixed** 和涉及 Breaking Changes 的条目**必须保留**

### 预发布版本处理

- **正式版本**： **必须汇总**其所有预发布版本的变更，不能只写“合并了 RC 的改动”
- **预发布版本**：保留独立的变更记录，作为历史追溯依据

---

## 三、章节结构

每个版本按以下顺序包含对应章节：

| 章节             | 是否必须     | 说明                                                 |
|------------------|--------------|------------------------------------------------------|
| Breaking Changes | 否（有则写） | **置顶**，破坏性变更必须醒目，说明影响范围和迁移方式 |
| Added            | 否（有则写） | 新增的功能、模块、接口、配置项                       |
| Changed          | 否（有则写） | 现有功能的变更、重构、性能优化、依赖升级             |
| Fixed            | 否（有则写） | 修复的问题，附带 issue 编号                          |
| Removed          | 否（有则写） | 移除的功能、代码、配置项                             |
| Security         | 否（有则写） | 安全相关修复（如有）                                 |

> 如果没有对应类型的变更，直接省略该小节，不写空章节。

---

## 四、书写规范

### 语言风格

- 使用中文，技术文档风格
- 每条变更用一句话概括，以动词的 **过去分词**开头：新增、重构、修复、移除、升级、优化
- 尽量具体，便于定位和追溯

### 条目书写

- 每个条目用 `-` 开头
- **必须包含足够的技术信息**：文件名、组件名、接口名、数据库表名等
- 附带关联的 issue 编号：`(#123)`
- 如果变更涉及多个文件或跨模块，用概括性描述加关键点

### 正反例

| ❌ 错误写法      | ✅ 正确写法                                                 |
|------------------|-------------------------------------------------------------|
| 优化了用户界面   | 重构 `EditRecord` 组件使用 store 获取状态列表               |
| 修复了空状态问题 | 修复点名页面无记录时布局跳动问题 (#42)                      |
| 改进了导入功能   | 重构导入组件布局：外部遮罩不可点击、移除关闭按钮 (#16, #18) |

### Added 章节的粒度

- 可独立存在的功能模块、组件、接口、配置项
- 每个新增项应是有 **独立价值**的代码产出
- 避免将多个不相关的新增合并为一条

### Changed 章节的范围

- 现有功能的逻辑变更
- 代码重构（不改变外部行为）
- 依赖版本升级
- 配置结构调整
- 性能优化

---

## 五、版本间变更汇总规则

### 正式版汇总预发布版本

正式版的各章节应包含其所有预发布版本的变更条目，但需：

1. **合并同类项**：同一功能在多个 RC 中的渐进式改进应合并为一条
2. **保留关键信息**：重要的 Breaking Changes 和架构变更必须保留
3. **去除琐碎条目**：工具链调整、内部日志优化等维护性变更可不纳入正式版，或在 Changed 中合并为“更新开发工具链配置”类概括条目

### 示例

多个 RC 中的零散条目：

```
rc.1: 新增表格排序功能
rc.2: 修复表格排序在空列表时崩溃
rc.3: 优化表格排序对中文姓名的支持
```

正式版合并为：

```
新增表格排序功能，支持中文姓名排序
```

## 六、示例

```markdown
# CHANGELOG

All notable changes to this project will be documented in this file.

---

## 1.0.0

### Breaking Changes

- 重构用户认证模块，`session` 表新增 `expires_at` 字段，旧数据需迁移 (#45)

### Added

- 新增 `UserService` 接口及配套 Repository 实现 (#40)
- 新增 `config/auth.toml` 配置文件，支持 JWT 过期时间自定义 (#42)

### Changed

- 重构 `LoginCommand` 改用新的认证服务，移除旧版密码加密方案 (#38)
- 升级 Rust 至 1.80 版本，同步更新各依赖 (#50)

### Fixed

- 修复并发登录时 session 冲突导致 panic 的问题 (#41)
- 修复 `UserRepository.find_by_email` 在邮箱为空时未返回错误的问题 (#43)

### Removed

- 移除 `legacy/password.rs` 及相关旧版加密函数 (#39)

---

## 1.0.1

### Fixed

- 修复并发登录时 session 冲突导致 panic 的问题 (#41)
- 修复 `UserRepository.find_by_email` 在邮箱为空时未返回错误的问题 (#43)

---

## 1.0.0-rc.1

### Added

- 新增用户认证模块基础架构 (#35)

### Fixed

- 修复登录接口在错误密码下未返回明确错误信息的问题 (#37)
```

## 七、检查清单

发布前，确认以下事项：

- [ ] 正式版已汇总所有预发布版本的变更
- [ ] Breaking Changes 已置顶且包含迁移说明
- [ ] 每条变更都有技术上下文，开发者能理解改动了什么
- [ ] 涉及问题修复的条目附带 issue 编号
- [ ] 没有出现用户视角的产品描述
- [ ] 版本号按时间倒序排列
