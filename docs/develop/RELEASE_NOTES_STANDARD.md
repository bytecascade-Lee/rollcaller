# RELEASE_NOTES.md 书写规范

> 本文档定义了 `RELEASE_NOTES.md` 的书写规范，适用于项目所有贡献者。

---

## 一、定位

**RELEASE_NOTES 面向最终用户**，回答的问题是： **“这个版本对我来说有什么变化？”**

- 语言通俗，避免代码级术语
- 聚焦用户可感知的变化，而非实现细节
- 帮助用户决定是否升级，以及升级需要注意什么

---

## 二、版本号规则

### 版本格式

```
## [版本号]
```

- 版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)：`主版本号.次版本号.修订号`
- 预发布版本附加 `-alpha.x` / `-beta.x` / `-rc.x` 后缀

### 版本排序

**按时间倒序排列**，最新版本在最上方。

### 预发布版本处理

- **预发布版本（RC/Alpha/Beta）** ：简要记录，篇幅不超过正式版的一半
- 预发布版本需在第一行说明“本版本包含上一预发布版本的全部内容”
- **正式版本**：汇总其所有预发布版本的用户可见变化，写成完整章节

---

## 三、章节结构

每个正式版本必须按以下顺序包含对应章节：

| 章节     | 是否必须             | 说明                                             |
|----------|----------------------|--------------------------------------------------|
| 版本亮点 | 是                   | 1-2 句概括本次更新最值得关注的内容，点明价值     |
| 新增功能 | 否（有则写）         | 用户能直接使用的新功能，按模块分点描述           |
| 体验改进 | 否（有则写）         | 性能提升、交互优化、界面打磨，不含技术细节       |
| 重要修复 | 否（有则写）         | 只列用户会遇到且影响使用的问题，一般 3-6 条      |
| 升级注意 | 有则写，无则写“暂无” | Breaking Changes、数据库迁移、配置变更，必须醒目 |
| 已知问题 | 有则写，无则写“暂无” | 当前版本已知但尚未修复的问题及临时应对方案       |

> 如果某个版本没有任何新增功能或修复，可跳过该章节，但“版本亮点”和“升级注意”仍需保留。

### 预发布版本的章节结构

预发布版本可简化为以下格式：

```markdown
## x.y.z-rc.n

本版本包含 x.y.z-rc. (n-1) 的全部内容，以下为增量变更：

- **新增**：（简要列出新增的用户可见功能）
- **改进**：（简要列出改进点）
- **修复**：（简要列出修复的问题）

> ⚠️ 如有破坏性变更或数据库迁移，必须在此醒目提示。
```

---

## 四、书写规范

### 语言风格

- 使用中文，口语化但不失专业
- 用主动语态，如“支持了…”“新增了…”而不是“…被支持”
- 避免“我们”，直接陈述事实

### 条目书写

- 每个条目用 `-` 开头
- 描述应独立成句，以动词开头：新增、优化、修复、调整、移除
- 不出现代码、文件名、函数名、类名
- 不出现 issue 编号（issue 编号归 CHANGELOG 管）

### 正反例

| ❌ 错误写法                                            | ✅ 正确写法                                              |
|--------------------------------------------------------|----------------------------------------------------------|
| 修复了 `EditRecord` 组件未选择更新项时按钮仍启用的问题 | 修复编辑考勤记录时未做任何修改但“确定”按钮仍可点击的问题 |
| 新增 `AttendanceStatusStore.svelte.ts` 全局状态管理    | 出勤状态改为数据库统一管理，为后续自定义状态打下基础     |
| 修复状态 ID 从 0 起始改为 1 起始导致的显示异常         | 修复部分场景下学生考勤状态显示错误的问题                 |

## 五、示例

```markdown
# 版本发布说明

> 如有问题或建议，欢迎在 [Issue](https://github.com/bytecascade-Lee/rollcaller/issues) 区提出。

---

## 1.0.0

### 版本亮点

一句话说明这个版本最值得关注的变化。

### 新增功能

- **功能模块**：功能描述，说明用户能做什么。
- **另一功能**：功能描述。

### 体验改进

- 优化了某流程，现在操作更顺畅。
- 界面某区域重新设计，信息更清晰。

### 重要修复

- 修复特定情况下崩溃的问题。
- 修复某功能在特定场景下失效的问题。

### 升级注意

本次包含数据库变更，升级前请备份数据。

### 已知问题

暂无。
```

## 六、检查清单

发布前，确认以下事项：

- [ ] 所有预发布版本的内容已合并到对应的正式版本
- [ ] 正式版本包含完整的“版本亮点”章节
- [ ] 没有出现代码/文件名/函数名
- [ ] 没有出现 issue 编号
- [ ] “升级注意”醒目且完整
- [ ] 版本号按时间倒序排列
- [ ] 链接（如 Issue 入口）可正常访问
