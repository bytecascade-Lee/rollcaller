# 导航架构：地址驱动的全局跳转体系

> 本文档以 **`refactor/global-route` 分支（v0.8.1 → HEAD，124 个提交）** 落地的导航体系为对象，描述它要解决的问题、选择的方向、各项机制的实现，以及尚未完成的部分。
>
> 涉及路径均相对仓库根。

---

## 1. 概览

### 1.1 一句话

位置由 **地址**表达（`#/<窗口名>/<段...>`），数据由 **载荷**附带。任何窗口、任何来源的跳转都走同一条路：判定归属 → 本窗口落地或交给后端投递给目标窗口 → 目标窗口按地址铺路并交付载荷。

### 1.2 出发点：v0.8.1 时的四个痛点

| # | 痛点                 | 具体表现                                                                                                                              |
|---|----------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| 1 | **窗口是孤岛**       | 打开另一个窗口只能调专用命令（`openHelpWindow` 等），**只能开到默认页**，无法指定"去哪个位置"                                         |
| 2 | **视图与地址无关**   | 切卡片 / 开弹窗是"存一个状态变量 + 模板 `if`"，`location.hash` 不反映它 ⇒ 刷新回默认、外部无法深链、重放同一位置会被幂等判断静默吃掉  |
| 3 | **命名靠约定**       | 全局单例 `overlayController` + 跨应用命名空间 `PopupName`，名字必须带前缀（`StudentEdit` / `RecordEdit`），**写错只在运行期静默失败** |
| 4 | **文档交叉链接脆弱** | 帮助文档的锚点与内链靠 `data-*` 标记 + 注解预处理（`@section` / `@link`）维持，一致性无守护                                           |

### 1.3 四条目标

| # | 目标               | 判据                                             |
|---|--------------------|--------------------------------------------------|
| 1 | 位置可被外部指定   | 任何来源都能"去 X"，且不必知道目标窗口的内部结构 |
| 2 | 地址与显示一致     | 地址是真源；刷新、重放、深链、前进后退自然一致   |
| 3 | 名字只有一个手写处 | 写错即**编译报错**，而非运行期静默失败           |
| 4 | 窗口间无第二套机制 | 跨窗口与同窗口走同一条路，只有"谁落地"不同       |

### 1.4 五条贯穿全文的原则

| # | 原则                         | 体现                                                                         |
|---|------------------------------|------------------------------------------------------------------------------|
| 1 | **路径 = 位置，载荷 = 数据** | 实体 id 属载荷，不进地址；payload 可 JSON 序列化、不可执行                   |
| 2 | **通用层只认 host**          | 通用层只做规范化 / 判归属 / 转发；其余段怎么解释是各域自己的事               |
| 3 | **域即窗口名**               | host 就是窗口名 ⇒ 后端不需要"域 → 窗口"映射表，`route` 第一段即目标          |
| 4 | **声明唯一，其余生成**       | 入口名的手写处只有 `meta.json`；类型、句柄、地址全部派生                     |
| 5 | **降级得体，不抛错**         | 非法地址原地不动、载荷非法退化为纯导航、锚点缺失回顶部、未装 router 静默忽略 |

## 2. 核心模型

### 2.1 地址

```
#/<host>/<seg1>/<seg2>/...
```

- `host` = 窗口名（`app` / `help`），小写、比较时大小写不敏感
- 其余段是不透明路径， **语法归各域**（help 是 `doc[/anchor]`，app 是 `入口链`）
- 地址 **永远只表达位置**，不携带任何数据

### 2.2 Action 与幂等

一次跳转 = `Action { route, payload? }`。幂等判据是 route 与 payload **都**相同；重放同一 Action 的语义是"重新应用初始状态"，不是"无事可做"（这一条在实现里踩过坑，见 §4.2）。

### 2.3 位置可否深链的判据

> 呈现只依赖 **可序列化输入**，且所需状态能由这些输入 + 导航时可满足的前置条件重建。

| 类型                  | 例子                                                           | 可否深链                                               |
|-----------------------|----------------------------------------------------------------|--------------------------------------------------------|
| 只吃 id               | `edit-student` / `delete-student`                              | 可以                                                   |
| 零输入                | `create-student` / `import-student`                            | 可以                                                   |
| 吃 DOM 引用或派生视图 | `export-student` / `export-record`（要 `anchor` 与 `display`） | **不可以**，只在本窗口"用户点了哪个按钮"的上下文里出现 |

## 3. 分层与文件

### 3.1 前端：`frontend/src/lib/routing/`（7 个手写 + 1 个生成）

| 文件                     | 职责                                                                                                                                                      |
|--------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| `address.ts`             | **L0 纯值**：`parseRoute` / `routeOf` / `canonicalRoute` / `canonicalAction` / `isRouteHref` / `hostOf`。只认语法，不认任何域                             |
| `router.ts`              | 工厂 `createRouter`：规范化 → 判归属（`handle` / `forward`）→ `hashchange` 兜底 → 首帧落点（`initial` 优先于 hash）                                       |
| `windowRouter.ts`        | **唯一模块级可变状态**的门面单例：`install` / `nav` / `currentRoute` / `replaceHash`。未安装时 `nav` 静默忽略                                             |
| `registry.ts`            | 落点注册表 `createEntryRegistry`，**每页 / 每窗口一张**：`register` / `interpret` / `unregister` / `open` / `close` / `isVisible` / `has`。只有叠加层注册 |
| `entries.ts`             | app 域纯函数：`ChildOf`（类型）、`chainOf`、`resolveAppEntry`、载荷读取 `readStudentIds`                                                                  |
| `appNavigate.ts`         | 类单例：app 域**唯一**的地址翻译者 —— `path` / `action` / `enter` / `leave`                                                                               |
| `helpNavigate.svelte.ts` | 类单例：help 域的**栈与落点全接管**（写 hash、加载文档、滚锚点、折叠树、入栈裁剪、前进后退）                                                              |
| `entries.generated.ts`   | **生成物**（勿手改）：`APP_HOST` / `AppEntryId` / `AppEntry` 句柄 / `APP_ENTRY_PARENT` + `HelpEntry` 深链句柄                                             |

另有 `lib/types/overlays.ts`：三个按页 / 窗口分组的叠加层名字类型（`StudentOverlayName` / `RecordOverlayName` = `ChildOf<…>` 派生；`HelpOverlayName` + `HelpOverlay` 句柄是帮助窗口的 **手写声明处**）。

### 3.2 后端：跨窗口投递（3 处，都是薄壳）

| 位置                                   | 内容                                                                                                                   |
|----------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| `backend/src/state/nav.rs`             | `NavState`：按窗口名维护**单槽**待取载荷 —— `put`（覆盖式 last-wins）/ `take`（取走并清空）/ `clear`（窗口销毁时清理） |
| `backend/src/cmd/nav.rs`               | `nav_open`（投递）/ `nav_take_pending`（取走）+ `NAV_WAKE_EVENT`（**不带载荷**）+ `host_of`（后端对 route 的唯一理解） |
| `backend/src/windows.rs::open_by_host` | 按 host 分发建窗；返回值表示"是否新建"                                                                                 |

三条刻意的选择：

- **单槽而非队列**：投递语义是"把窗口带到某个状态"，不是消息；最新一次覆盖前一次，连点链接不会排队弹两次。
- **存着等取，而非广播**：目标窗口可能是懒创建的，建窗那一刻前端还没开始监听，广播必丢；载荷先落后端、由前端主动取，抹平了时机差。
- **事件不带载荷**：载荷只走 pending 一条通路 ⇒ 不可能出现"事件里的载荷"与"取到的载荷"两份真相；重复唤醒天然幂等。 **没有单独的 ready 命令**——前端挂载后取一次，"取走"这个动作本身就是就绪信号。

## 4. 关键机制

### 4.1 三种落点，一种入口

| 落点           | 呈现方式                        | 注册 handler |
|----------------|---------------------------------|--------------|
| 卡片（平面）   | 当前地址链的**链首**投影        | 否           |
| 浮层（叠加层） | 对应 handler 的 `open(payload)` | 是           |
| 帮助文档       | `helpNavigate` 接管落点         | 否           |

**卡片刻意不注册 handler**：若卡片也注册，"链首"与"当前卡片"就成了两份状态，可能互相漂移；而投影不可能漂移。"打开某个页面"只是 **链长为 1** 的情形，不是特例。

### 4.2 转换语义：按共同前缀 diff

```
shared = 新旧链的共同前缀长度
旧的 shared 之后各段：逆序 close
新的 shared 之后各段：顺序 open（载荷只交给最深的那一个）
整条链相同（重放同一地址）：diff 无动作 ⇒ 单独补一次目标的 open
```

| 场景                              | 结果                                                                        |
|-----------------------------------|-----------------------------------------------------------------------------|
| `edit-student` → `delete-student` | 公共前缀含卡片 ⇒ 卡片纹丝不动                                               |
| 切到无关卡片                      | 前缀为空 ⇒ 全关再开                                                         |
| 重放同一地址                      | 补一次 `open` —— 否则"地址停在目标、浮层早已关闭"的状态下重放会**静默失效** |

最后一格是本体系里最反直觉的一处：因为 **关闭也回退地址**（§4.3），"地址在目标但浮层已关"是常见状态；没有这条补充，用户第二次点同一个入口会毫无反应。

### 4.3 不变量：浮层可见 ⇔ 它是当前地址的链尾

两条规则成对成立：

- **打开一律走地址** `appNavigate.enter(entry, payload)` —— 哪怕目标就在本窗口。内部发起与外部深链因此走同一条路，不存在"绕过地址打开的浮层"。
- **关闭一律回退地址** `appNavigate.leave(entry)` —— 回退到父级；注册表里的 `close` 只负责 **真正的隐藏**，由转换语义调用。

**护栏**：`leave` 先比对"当前地址是否就是自己"，不是则不动。不设这条会出现——浮层锚定在工具栏上，用户点侧边栏切卡片（导航先落地），浮层的 `clickOutside` 随后触发， **第二次导航会把刚切过去的卡片拽回来**。

代价明确：关闭浮层会让可观测的地址跟着退回去。这正是"地址诚实"的收益而不是副作用——地址不再撒谎，重放与深链才成立。

### 4.4 父链严格

| 阶段   | 校验                                                                                                                 |
|--------|----------------------------------------------------------------------------------------------------------------------|
| 生成期 | `parentId` 必须存在于表中、禁自指、禁成环                                                                            |
| 运行期 | `resolveAppEntry` 要求「最后一段是入口名 + 段数等于链长 + 逐段与 `parentId` 链一致」，任一不符返回 `null` ⇒ 原地不动 |

**为什么必须严格**：完整路径是 **承重件**——铺路就是按这条链自顶向下 show 的。若祖先段只是装饰，它迟早腐烂（旧的 `owner` 字段就是这么死掉的）。

### 4.5 载荷交付（现状三种并存）

| 方式           | 例子             | 说明                                                                                                                                |
|----------------|------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| **快照**       | `delete-student` | `open(payload)` 把 `{ids}` 快照进组件内部变量，之后只认它。快照只存 id、展示行按"学生仍存在"派生 ⇒ 数据后到会自愈，也不必命令式清理 |
| **解释器**     | `edit-student`   | 页面注册 `interpret(id, fn)`，在 `open` 之前把载荷翻译成本页状态（选中集）。**页面是载荷的唯一解释者**                              |
| **只读 props** | `export-*`       | 需要 `display`（派生视图）与 DOM `anchor`，塞不进小载荷                                                                             |

这一块 **尚未收敛**，见 §7.1。

### 4.6 帮助域

- `HelpAddress`（`lib/utils/helpAddress.ts`）是帮助地址的 **唯一解释者与拼装者**；锚点语法 kebab，刻意避开 DOMPurify 的保留词（`title` / `location` / `body`…）。
- `helpNavigate` 接管栈与全部落点；窗口只交出 **视口端口** `install({scrollTo, foldTree})`，DOM 不进类。
- **栈只记用户点击**：靠一次性意图位 —— `open()` 置位 → router 的唯一出口 `apply()` 同步消费并复位。跨窗口投递与冷启动载荷属于"送达"，把栈 **重置成只剩这一条**（于是"上一步"不会退到一个本窗口没主动去过的位置）。
- 加载序号判断在途加载是否已被更晚的导航取代，避免旧结果覆盖新状态。

### 4.7 声明 → 生成 → 类型约束链

```
app/meta.json   （唯一手写处：id + parentId，扁平节点树）
      │  scripts/generate_routing_entries.py
      ▼
entries.generated.ts
      ├─ AppEntryId           字面量联合（补全 + 写错即报错 + 全仓可搜）
      ├─ AppEntry             camelCase 句柄 → kebab 入口名
      └─ APP_ENTRY_PARENT     入口 → 父入口
```

帮助段在同一份文件里：`HelpEntry`（句柄 →
**完整地址**），由 `help/meta.json` 的文档树 + 各文档 md 的 `{#anchor}` 派生；文档源既可能是 `resources/help/<id>/` 目录，也可能是仓库根同名文件（README / LICENSE / CHANGELOG / RELEASE_NOTES）。

名字出现在三处、全部受类型约束： **联合类型成员**、`register` 实参、`enter` 实参。于是应用代码里 **不出现入口名字面量**。

`ChildOf<P>` 由 `parentId` 推导"某入口的直接子入口"，页面写 `EntryRegistry<ChildOf<"student-management">>` ⇒ 在本页写"记录页的浮层名"会 **编译期被拦下**。

生成器自带：`--check`（与声明比对，不一致非零退出）、声明校验（父存在 / 不自指 / 不成环）、句柄唯一性校验；`beforeDevCommand` 前置生成。

## 5. 一次跨窗口跳转的完整链路

以"帮助窗口的按钮 → 删除主窗口里某批学生"为例（ **这条链是端到端验证过的**）：

```
① appNavigate.enter(deleteStudent, {ids})    帮助窗口内发起
② router.go → 规范化 → host 是 app ≠ help ⇒ forward
③ NavCommand.navOpen → 后端 nav_open
     host_of(route) → open_by_host(建窗或唤前台) → put(pending) → emit_to 唤醒
④ app 窗口前端：NAV_WAKE_EVENT → navTakePending → router.go
⑤ handle → resolveAppEntry（严格校验父链）→ transition（共同前缀 diff）
⑥ registry.open(deleteStudent, {ids}) → 弹窗快照 → 确认框
⑦ 用户确认 → 删除 → appNavigate.leave(deleteStudent) → 地址回退到卡片
```

**冷启动变体**：目标窗口不存在 ⇒ 建窗且 **不发事件**，载荷躺在单槽里；目标前端挂载后取一次 —— "取走"本身就是就绪信号。

## 6. 降级策略一览

| 情形                | 行为                                               |
|---------------------|----------------------------------------------------|
| 地址非法 / 父链不符 | 原地不动 + 报错日志（绝不半应用）                  |
| 载荷非法或为空      | 退化为纯导航（只切位置，不弹窗）                   |
| 锚点不存在          | 滚到文档顶部                                       |
| router 未安装       | 静默忽略                                           |
| 入口名查询          | 用 `Set` 而非 `in`，避免 `toString` 之类原型键命中 |

## 7. 未完成 / 已知缺口

### 7.1 payload 没有设计

现状是 **三种方式并存**（§4.5），没有统一契约。根子上有一个结构性事实：

> 因为"打开一律走地址"， **内部发起也要绕地址一圈**。payload 在 `appAction` 处就被削成 `Payload = Record<string, unknown>`，于是内部发起与外部深链在 `registry.open` 处 **完全合流，都是 `unknown`**。

由此：

- **"构造方有类型、所以不必解析"做不到**——类型在构造点之后就不存在了。组件不得不对"自己刚构造的数据"做运行期校验（`readStudentIds` + 空判断），而"载荷非法 ⇒ 降级"这条契约在多个组件里各写一遍。
- 今天 `enter(deleteStudent, {id: 1})`（字段名写错） **不报错**，因为第二个参数是宽类型。

可行的方向（未实现）：把契约做成 **两个投影** —— 类型管编译期（约束 `enter` 的第二参数），`parse` 管运行期（约束来自地址的 `unknown`），并把解析收敛到注册表 **一次**完成；有契约的入口收精确形状，无契约的入口不许传载荷。

**实现思路**：引入一张按入口 id 索引的 **契约表**（键受 `AppEntryId` 约束，写错即编译报错）。契约就是一个 `parse(raw: unknown): T | null`，而 `T` 从它的返回类型反推（`NonNullable<ReturnType<…>>`）—— 于是
**形状只写一处**：编译期用它约束 `enter` 的第二参数，运行期用它解析来自地址的值。注册时把 `parse` 一并交给注册表，`open(id, raw)` 内部解析
**一次**：失败即统一的那次降级，`handler.open` 收到强类型。这样组件里的 `readStudentIds` 与各处空判断全部消失，`interpret` 也可随之删除（`edit-student` 改成快照后就不需要它）。跨窗口的载荷来自 JSON，
**运行期校验这一点省不掉**。

### 7.2 帮助文档跳转到 app 界面的入口没有设计

两处缺口：

-
**文档正文里的跨域链接没有处理路径。** 渲染期只改写"帮助文档之间的相对链接"（`HelpAddress.fromDocLink`）；点击期先判 domain，`#/app/...` 拿不到 `HelpAddress` ⇒ 不被拦截、交回浏览器原生。它会经帮助窗口的 `hashchange` 兜底再 `forward` 投递给 app 窗口 ——
**这条路径从未被有意设计，也未被验证**，且副作用明确： **帮助窗口自身的地址会被改成 app 的地址**（地址撒谎，与 §4.3 的不变量冲突）。
- **缺少一个"跳到 app 某界面"的 UI 组件。** 目前只有帮助窗口标题栏上一个调试用按钮，它不是产品功能。

**实现思路**：① **最小** —— 渲染期把 `#/<非 help 的 host>/...` 也识别为"应用内路由"（现在只识别"帮助文档相对链接"），点击期交给宿主的转发通道， **而不是放给浏览器原生处理**（放给浏览器就会写脏帮助窗口自己的地址）。②
**更强** —— 在文档里用一个显式的跳转标记渲染成按钮，点击时构造完整 `Action`（ **可以带载荷**）走 `WindowRouter.nav`；① 只能传位置，② 能传参数，若将来要"从文档一键预填某个界面"，② 是唯一的形状。另需顺带定一条产品语义：
**从帮助跳到 app 后，帮助窗口是否留在原地**（当前实现会留在原地，因为它只是转发）。

### 7.3 调用链过深没有处理

一次同窗口打开要穿过：

```
appNavigate.enter → action → WindowRouter.nav → router.go → canonicalAction
  → handle → resolveAppEntry → chainOf → transition → registry.open → handler.open
```

跨窗口再多两跳 IPC。当前没有任何缓解手段：没有中间层缓存/短路、没有调试追踪（只有非法地址的 `console.error`），且 `transition`（转换语义）与路由分居两个文件（前者在 `App.svelte`）。

**实现思路**：三条可叠加，但 **都不靠"合并层"来缩短链条** —— 现在每层只做一件事，合并只会把职责揉在一起。①
**可观测**（性价比最高）：给一次导航分配一个 trace id，在 `router.go` / `transition` / `registry.open` 三处打统一日志，先解决"看不清"；②
**短路**：把"目标入口未注册"从 mount 时的完整性断言提前到转换之前（现在非法注册要等 ready 后才发现）；③
**内聚**：把 `transition` 从 `App.svelte` 抽进 `routing/` —— 它本来就是纯逻辑（输入新旧链与载荷），抽出来顺带获得可测性（见 §7.5）。

### 7.4 部分文件注释杂乱

同一批文件里注释风格不统一：既有"这是什么"的一句话，也有成段的设计论证、与旧实现的对比、被否决的方案。 **已决定暂不清洗**（导航仍在演进，改完还会长回来），先记账。

**实现思路**：判据定为「注释回答 **这里不能怎么做**，不回答"我为什么这么做"」。保留三类：名字不自明时的一句话、 **反直觉的约束**（例如 `leave` 的护栏 —— 不写明就会有人当冗余删掉）、跨文件不变量的
**一行**。删掉：设计论证、与旧实现的对比、被否决的方案、举例、命名解释。执行上 **不做全仓一次性清洗**，先拿三个骨架文件（`entries.ts`、`appNavigate.ts`、`App.svelte::transition`）做样板，其余随手删。注意
**生成器模板里的注释会写回生成物**，要一并压。

### 7.5 单元测试没有实现完整覆盖

已有 `frontend/tests/routing.test.mjs`（13 项，`pnpm test`），覆盖纯逻辑：

- `address` 原语（切分 / 组装 / 规范化幂等 / 非应用内地址）
- `chainOf`、`resolveAppEntry`（父链严格、原型键不命中）、`readStudentIds`

- 生成物 ↔ `app/meta.json` 一致、`HelpEntry` 地址合法且不重复

## 8. 关键决策备查

| 决策点           | 选择                          | 理由                                      | 代价                                             |
|------------------|-------------------------------|-------------------------------------------|--------------------------------------------------|
| 位置与数据的划分 | 路径 = 位置，载荷 = 数据      | 地址可比较、可写 href、幂等判定简单       | 载荷必须可 JSON 序列化（`bigint` 要转 `number`） |
| 后端对地址的理解 | 只认第一段（host）            | 无需"域 → 窗口"映射表，也不必镜像前端类型 | 段语义完全归前端，后端无法校验路径合法性         |
| 跨窗口投递       | 单槽 pending + 无载荷唤醒事件 | 抹平懒建窗的监听时机；载荷只有一份真相    | 连续投递只保留最后一次（刻意的 last-wins）       |

| 卡片的呈现 | 不注册 handler，用链首投影 | 避免"链首"与"当前卡片"两份状态 | 注册完整性断言要显式排除根入口 |  
| 打开与关闭 | 都走地址 | 地址成为全时真源，重放/深链/刷新自然一致 | 关闭会改变可观测地址（这是收益的一半） |  
| 名字来源 | `meta.json` 生成，不手写常量表 | 改名即编译报错，且全仓可搜 | 必须跑生成器；生成物入库且禁止手改 |  
| 帮助的栈 | 归 `helpNavigate`，只记用户点击 | 栈与"是否入栈"是同一事实的两面，分开必漂移 | 一个类承担较多，窗口只留视口端口 |  
| 测试设施 | 裸 node 跑纯逻辑，不引框架 | 零依赖，且能 import 生产代码 | 测不到 `.svelte.ts` 与组件 |

---

## 9. 后续方向

1. **payload 契约**（§7.1）：类型给编译期、`parse` 给运行期，解析收敛到注册表一次。
2. **帮助 → app 的跨域入口**（§7.2）：渲染期识别 `#/<其它 host>/...` 并交宿主投递，或提供显式的跳转组件。
3. **把 `App.svelte::transition` 的共同前缀 diff 抽成纯函数** —— 它是目前唯一"重要且测不到"的逻辑。
4. **生成器 `--check` 接进 `pnpm check` / CI**，让"生成物 == 声明"有一条命令守护。
5. 需要覆盖栈与组件时再引 vitest。
