# CHANGELOG.md 书写规范

> 位置：`docs/standards/CHANGELOG_STANDARD.md`，适用对象为仓库根目录的 `CHANGELOG.md`。
> 与 `docs/standards/Git.md` §6.2 / §6.3 的发布流程配套：发布前须新增本章节并更新顶部目录。
> 面向用户的版本说明见 `docs/standards/RELEASE_NOTES_STANDARD.md`。

---

## 一、定位

**CHANGELOG 面向开发者**，回答的问题是：**代码层面发生了什么变化？**

- 记录代码与架构层面的变动
- 用于排查缺陷、追溯历史、评估升级风险
- 不面向最终用户，不写产品描述

---

## 二、版本号与标题

### 标题格式

````text
## 0.8.2 {#0-8-2}
````

- 版本号遵循[语义化版本](https://semver.org/lang/zh-CN/)：`主版本号.次版本号.修订号`，预发布版本附加 `-alpha.x` / `-beta.x` / `-rc.x`
- 标题中的版本号**不带 `v` 前缀**，`v` 只出现在 git tag 上
- 锚点由版本号派生：`.` 与 `-` 一律替换为 `-`（`0.3.0-rc.1` → `{#0-3-0-rc-1}`）
- **禁止写成 `## [0.8.2]` 或 `## v0.8.2`**：顶部目录依赖锚点跳转，标题格式须与 `RELEASE_NOTES.md` 保持一致

### 版本排序

**按时间倒序排列**，最新版本在最上方。

### 补丁版本

补丁版本（修订号递增，如 1.0.0 → 1.0.1）是正式发行版本：

- 每个补丁版本**单独成章**，不合并或汇总到其他版本
- 下一个次版本或主版本发布时，补丁版本的历史记录**保留不变**
- 章节结构可精简（省略 Added、Removed 等），但 **Fixed** 与涉及 Breaking Changes 的条目**必须保留**

### 预发布版本

- **正式版本**：**必须汇总**其全部预发布版本的变更，不能只写「合并了 RC 的改动」
- **预发布版本**：保留独立章节，作为历史追溯依据

## 三、顶部目录

文件开头固定为一段目录，逐条列出所有版本，顺序与正文章节一致（倒序）：

````text
## 目录

- [0.8.2](#0-8-2) — Address-driven in-app routing, multi-sheet import (.xls included).
- [0.8.1](#0-8-1) — Automatic updates after refactoring, CLI diagnostics.
````

- 每行格式：`- [<版本号>](#<锚点>) — <一句话摘要>`
- 摘要用**英文**一句话、以句号结尾，便于开发者快速扫读；章节正文仍用中文
- 新增版本时，同步在目录列表**顶部**插入一行

---

## 四、章节结构

每个版本按以下顺序包含对应章节：

| 章节             | 是否必须     | 说明                                 |
|:-----------------|:-------------|:-------------------------------------|
| Breaking Changes | 否（有则写） | **置顶**，说明影响范围和迁移方式     |
| Added            | 否（有则写） | 新增的功能、模块、接口、配置项       |
| Changed          | 否（有则写） | 现有功能的变更、重构、性能优化、依赖升级 |
| Fixed            | 否（有则写） | 修复的问题，附 issue 编号（如有）    |
| Removed          | 否（有则写） | 移除的功能、代码、配置项             |
| Security         | 否（有则写） | 安全相关修复（如有）                 |

> 没有对应类型的变更时直接省略该小节，不写空章节。

## 五、书写规范

### 语言风格

- 章节正文使用中文，技术文档风格
- 每条变更用一句话概括，以动词开头：新增、重构、修复、移除、升级、优化
- 尽量具体，便于定位和追溯

### 条目书写

- 每个条目以 `-` 开头
- **必须包含足够的技术信息**：文件名、组件名、接口名、数据库表名等
- 有对应 issue 时在条目末尾附 `(#123)`；无 issue 可省略
- 变更跨多个文件或模块时，用概括性描述加关键点

### 正反例

| 错误写法         | 正确写法                                                    |
|:-----------------|:------------------------------------------------------------|
| 优化了用户界面   | 重构 `EditRecord` 组件，改用 store 获取状态列表             |
| 修复了空状态问题 | 修复点名页面无记录时布局跳动的问题 (#42)                    |
| 改进了导入功能   | 重构导入组件布局：外部遮罩不可点击、移除关闭按钮 (#16, #18) |

### Added 的粒度

- 可独立存在的功能模块、组件、接口、配置项
- 每个新增项应是有**独立价值**的代码产出
- 不将多个不相关的新增合并为一条

### Changed 的范围

- 现有功能的逻辑变更
- 代码重构（不改变外部行为）
- 依赖版本升级
- 配置结构调整
- 性能优化

## 六、版本间变更汇总

### 正式版汇总预发布版本

正式版的各章节应包含其全部预发布版本的变更条目，但需：

1. **合并同类项**：同一功能在多个 RC 中的渐进式改进合并为一条
2. **保留关键信息**：重要的 Breaking Changes 与架构变更必须保留
3. **去除琐碎条目**：工具链调整、内部日志优化等维护性变更可不纳入正式版，或在 Changed 中合并为「更新开发工具链配置」这类概括条目

### 示例

多个 RC 中的零散条目：

```text
rc.1: 新增表格排序功能
rc.2: 修复表格排序在空列表时崩溃
rc.3: 优化表格排序对中文姓名的支持
```

正式版合并为：

```text
新增表格排序功能，支持中文姓名排序
```

## 七、示例

````markdown
# CHANGELOG

All notable changes to this project will be documented in this file.

---

## 目录

- [1.0.1](#1-0-1) — Fix session conflict on concurrent login.
- [1.0.0](#1-0-0) — User authentication module, JWT config.
- [1.0.0-rc.1](#1-0-0-rc-1) — Authentication foundation.

---

## 1.0.1 {#1-0-1}

### Fixed

- 修复并发登录时 session 冲突导致 panic 的问题 (#41)

---

## 1.0.0 {#1-0-0}

### Breaking Changes

- 重构用户认证模块，`session` 表新增 `expires_at` 字段，旧数据需迁移 (#45)

### Added

- 新增 `UserService` 接口及配套 Repository 实现 (#40)
- 新增 `config/auth.toml` 配置文件，支持 JWT 过期时间自定义 (#42)

### Changed

- 重构 `LoginCommand` 改用新的认证服务，移除旧版密码加密方案 (#38)
- 升级 Rust 至 1.80 版本，同步更新各依赖 (#50)

### Fixed

- 修复 `UserRepository.find_by_email` 在邮箱为空时未返回错误的问题 (#43)

### Removed

- 移除 `legacy/password.rs` 及相关旧版加密函数 (#39)

---

## 1.0.0-rc.1 {#1-0-0-rc-1}

### Added

- 新增用户认证模块基础架构 (#35)

### Fixed

- 修复登录接口在错误密码下未返回明确错误信息的问题 (#37)

---
````

## 八、检查清单

发布前逐项确认：

- [ ] 标题格式为 `## <版本号> {#<锚点>}`，版本号不带 `v`，且与计划发布的 tag 一致
- [ ] 顶部目录已新增对应行，链接可跳转到本章节
- [ ] 正式版已汇总全部预发布版本的变更
- [ ] Breaking Changes 已置顶且包含迁移说明
- [ ] 每条变更都有技术上下文，开发者能理解改动了什么
- [ ] 涉及缺陷修复的条目在存在 issue 时附编号
- [ ] 没有出现用户视角的产品描述
- [ ] 版本按时间倒序排列
